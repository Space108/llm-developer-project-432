# 0002. SQL-файлы вместо Alembic

## Контекст

В практике темы схема создавалась запросом «создать таблицу, если не существует» при подключении. Дальше таблиц станет больше, появятся индексы pgvector, генерируемые колонки и запросы с оконными функциями.

## Решение

Каталог `db/migrations` и раннер `python -m app.core.migrate`. Применённые версии пишутся в `schema_migrations`. Повторный запуск уже записанную миграцию не выполняет. Первая миграция включает расширение `vector` и создаёт таблицу версий.

Инструмент записан рядом с решением о каркасе (`0001-agent-stack.md`).

## Альтернативы

Alembic. Для одной таблицы задач его хватило бы.

## Компромиссы

Автогенерации схемы нет. Зато SQL, которым потом будут пользоваться поиск и индексы, не спрятан за прослойкой.

## Когда пересмотреть

Если миграций станет много и ручной порядок перестанет быть обзоримым, либо если схема начнёт жить только в моделях ORM и SQL перестанет быть основным способом её менять.
